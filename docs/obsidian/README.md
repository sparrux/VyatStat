- [[Requirements]] - Полный набор требований к системе. Включает функциональные возможности, ограничения, нефункциональные требования и бизнес-правила. Отвечает на вопрос **«Что должна делать система?»**.

- [[Use Cases]] - Сценарии взаимодействия пользователей с системой. Показывает последовательность действий для достижения конкретной цели и помогает проверить полноту требований. Отвечает на вопрос **«Как пользователи будут работать с системой?».**
	- [[Регистрация пользователя]]
- [[Architecture]] - Описание технической структуры приложения: компонентов, модулей, взаимодействий, API, базы данных, интеграций и архитектурных принципов. Отвечает на вопрос **«Как система будет построена?»**.
- [[Data Model]] - Логическая модель данных: сущности, атрибуты, связи, диаграммы, структуры хранения и ограничения целостности. Отвечает на вопрос **«Какие данные хранит система и как они связаны?»**.
- [[UI]] - Документация пользовательского интерфейса: экраны, навигация, макеты, пользовательские потоки и требования к отображению информации. Отвечает на вопрос **«Что увидит пользователь?»**.

- [[Decisions]] - Журнал архитектурных и технических решений (ADR). Каждая запись фиксирует проблему, принятое решение, причины выбора и последствия. Позволяет понять историю развития проекта и избежать повторного обсуждения уже принятых решений.

- [[Tasks]] - План разработки: задачи, backlog, этапы реализации, приоритеты, технический долг и идеи для будущих версий. Отвечает на вопрос **«Что необходимо сделать дальше?»**.
